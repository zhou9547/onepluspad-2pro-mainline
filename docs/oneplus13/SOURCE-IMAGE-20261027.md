# Complete RAM image from this branch

Run **OnePlus 13 fresh source image** (`oneplus13-source-image.yml`) on this
branch, or its **OnePlus 13 current image from source** wrapper. No uploaded
secrets or local owner files are required to produce the complete experimental
image for the qualified **PJZ110 24 GB / AA569** configuration.

Kernel, signed-snapshot Ubuntu GNOME and patched A830v1 Mesa build in parallel.
Assembly uses only products of the same workflow and commit, not old Actions
images. The checked-in `devices/oneplus13/qualified-data` contains all 71 firmware
files, display profile, calibrated DTB and boot geometry used by run90. These
proprietary binaries are data inputs, not generated by Linux source compilation.
Their original vendor terms apply; see that directory's `PROVENANCE.md`.

The artifact **`complete-ram-image-<commit>`** contains:

- `boot-desktop-ram-experimental.img`: Android v2 temporary RAM boot image,
  matched kernel/native module closure, validated display profile and DTB.
- `rootfs.squashfs`: full GNOME userspace, matched modules, fresh Mesa, all
  qualified firmware, WiFi authentication and Bluetooth/OBEX components.
- `manifest.json`, `complete-verification.json`, `SHA256SUMS`, initramfs and DTB.

No WiFi name/password, LAN test address, USB serial, MAC identity, access token,
private key, original device evidence or raw partition image is included. New
per-image session nonces identify a RAM session, not an owner's physical device.
The old DTB boot arguments are removed before publication and regenerated at
packaging. Network configuration must be supplied at runtime in RAM.

## Build verification and actual hardware result

By owner request, QEMU is **off by default**. Every build still verifies source
locks, component SHA-256, boot sections, module release, DTB compatibility,
firmware closure in the actual final SquashFS, and the full native display entry.
It does not label compilation as a new hardware test. Set workflow input
`runtime_qemu: true` only when runtime diagnostics are needed.

Run90 tested the source-built configuration: target scan, authentication, DHCP,
default route and WiFi-interface-bound HTTP 200 passed. Automatic Android return
took 109.2 seconds; seven baseline properties matched; no partition writes.
The successful historical build supplied the same qualified data locally;
publication and CI packaging now remove that remaining local-data dependency.
New CI artifacts have their own build hashes and are not falsely labeled run90.
HTTPS is diagnostic, not the owner's current WiFi acceptance criterion.

Previously qualified display, GPU, touch, GNOME settings/screen keyboard,
Bluetooth file transfer and battery support remain in the image. The explicit
RAM-only `/usr/libexec/oneplus13-qualified-bringup --all` starts these guarded
features; `--wifi` starts only the automatic network acceptance prerequisites.
Unqualified audio, camera, sensor streams, suspend and new SAR transport remain
gated. This is preservation of yesterday's functions, not full new port coverage.

## Local equivalent

Use native ARM64 Linux and a fresh Git checkout in a disposable build VM:

```sh
bash tools/oneplus13/source-image.sh kernel
bash tools/oneplus13/source-image.sh rootfs
bash tools/oneplus13/source-image.sh mesa
bash tools/oneplus13/source-image.sh assemble
bash tools/oneplus13/source-image.sh complete
```

Results are in `out/oneplus13-complete-image`. Optional QEMU:
`export ONEPLUS13_SOURCE_QEMU=true` before these commands. The signed frozen
Ubuntu snapshot is retained; bounded retries handle transient provider 503s.
The build does not weaken archive signature checks or TLS verification.

## Temporary RAM operation

Boot image and rootfs must remain paired by their manifest hashes. Supply the
rootfs with the repository's `tools/oneplus13/serve-rootfs.py` and use only the
explicit registered device for temporary `fastboot boot`. The build workflow
never contacts a phone. Do not flash, repartition or persistently install it.
Hardware operation requires a separately reviewed recovery/identity plan.

The pre-handoff initramfs watchdog is 600 seconds; it does **not** survive
`switch_root`. The rootfs arms its own 300-second systemd deadline. An authorized
host test may arm a shorter early-return timer, as run90 did. These are recovery
mechanisms, not a guarantee against every possible hardware failure.

Legacy `--private-inputs` packaging remains available for local, unreviewed
datasets, but is not used by Actions and does not allow publishing those inputs.
