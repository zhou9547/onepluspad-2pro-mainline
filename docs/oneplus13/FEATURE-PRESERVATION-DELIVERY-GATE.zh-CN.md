# 后续镜像必须保留已通过功能

机主要求后续交付保留已测试好的显示、触摸、GPU、桌面/设置/屏幕键盘、
WiFi、蓝牙文件发送及电池基础功能。不能把无线禁用的隔离诊断稿继续称为
完整升级，也不能把不同镜像的历史通过项拼成一套全功能系统。

功能交付前运行 `tools/oneplus13/verify-preserved-features.py`，提供本轮证据
目录及实际boot/rootfs/payload三件文件。门禁重新计算哈希、匹配执行方案与
实际启动标记，核对七项Android前后基线、零分区写入、显示、硬件GPU/项目
Mesa、普通用户桌面与WiFi组合、扫描/认证/IPv4/路由/证书HTTPS、蓝牙控制器
及发送/OBEX组件、触摸设备、电池和只读存储。任一项缺失，退出2并输出
delivery_eligible=false，不能作为完整功能交付版。

该工具不授予真机授权，不认证RF功率策略，也不代填机主的实际触摸、视觉或
蓝牙对端收件结果。独立原生内核Image构建通过不等于配套桌面已可交付。

run82/83保持原联网无线组合，仅替换成本机核对过的ADSP/GPU输入；旧来源
限制原文件与全部停止账本保留，具体范围调整有独立记录，不扩展到新无线
固件或新SAR设置。两轮均自动恢复Android、七项一致。run83实际发现50个AP
行、38个不同的可见SSID，但指定目标未发现，完整联网门禁仍失败。

验证器现只请求一次指定SSID扫描，随后最多3次/10秒读取缓存；记录数量而
不公开网络名称。该方式覆盖定向发现及缓存异步更新，不修改频域/功率、
重置驱动、重载模块或循环请求扫描。30项Linux检查和7项交付门禁检查通过；
隐藏热点与目标当前可用性仍须实际验证，不据此猜测本轮失败原因。
